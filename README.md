# TechStore

REST-сервис магазина техники на Java 17, Spring Boot, Spring Data JPA и PostgreSQL.
Поддерживает каталог товаров, пользователей, справочники и скидки. Для работы с API
используется Swagger UI.

## Запуск

Нужны JDK 17 или новее и Docker Compose. Maven Wrapper включён в проект.

```sh
make run
```

Команда запускает PostgreSQL в Docker, дожидается готовности базы и запускает
Java-приложение через Maven в текущем терминале.

- Swagger UI: http://localhost:8081/swagger-ui.html
- REST API: http://localhost:8081/api/products
- OpenAPI: http://localhost:8081/v3/api-docs

Для остановки приложения нажать Ctrl+C, затем остановить базу:

```sh
make down
```

Данные сохраняются в Docker volume. При первом запуске загружаются зависимости
Maven, образ PostgreSQL и начальные справочники.

### Команды

| Команда | Действие |
|---|---|
| `make` | Список команд |
| `make build` | Чистая сборка JAR и тесты |
| `make test` | Запуск тестов без базы данных |
| `make run` | Запуск базы и приложения |
| `make up` | Запуск только базы |
| `make down` | Остановка базы с сохранением данных |
| `make logs` | Журнал PostgreSQL |
| `make status` | Состояние контейнера |
| `make clean` | Удаление результатов сборки |

Без Make: `./scripts/run.sh` для запуска, `./mvnw clean verify` для сборки.
Для запуска в IntelliJ IDEA открыть проект как Maven-проект, выполнить `make up`
и запустить `TechStoreApplication`.

## Настройки

| Параметр | Значение по умолчанию |
|---|---|
| Адрес PostgreSQL | `localhost:5434` |
| База данных | `techstore` |
| Пользователь | `techstore` |
| Пароль локальной базы | `techstore_local` |
| Порт приложения | `8081` |

Compose запускает только PostgreSQL. Java-приложение работает на компьютере.
Настройки локального окружения задаются в `.env` по образцу `.env.example`.
Скрипт запуска читает `.env`; при запуске из IDE переменные нужно указать
в конфигурации запуска отдельно.

Приложение использует `DB_URL`, `DB_USER`, `DB_PASSWORD` и `PORT`.
`DB_PORT` задаёт опубликованный порт контейнера; скрипт использует его при
формировании `DB_URL`. Изменение пароля в `.env` не меняет пароль уже созданной базы.

Таблицы и справочники создаются при первом запуске PostgreSQL с пустым volume:

- `db/01-schema.sql` — таблицы и ограничения;
- `db/02-java-support.sql` — последовательность артикулов и хранение скидок;
- `db/03-reference-data.sql` — категории, характеристики и бренд `DemoBrand`.

Hibernate проверяет соответствие сущностей схеме (`ddl-auto=validate`).
Повторный запуск сохраняет данные и не выполняет эти скрипты заново.
Команда `docker compose down -v` удаляет volume вместе с данными.

## Работа с API

В Swagger операции разделены на товары, пользователей, справочники, скидки
и расширенные JSON-запросы.

### Товары

Для добавления товара открыть нужную категорию в группе «1. Товары», нажать
**Try it out**, заполнить название и цену, проверить остальные поля и нажать
**Execute**. Ответ `201` содержит созданный товар и его артикул.
Бренд, указанный в форме, создаётся автоматически, если его ещё нет.

`GET /api/products` возвращает список товаров. Фильтры: `name`, `brand`, `category`,
`minPrice`, `maxPrice`, `available`. Условия можно сочетать. Нумерация страниц
начинается с нуля; размер страницы — от 1 до 100.

```text
GET /api/products?category=SMARTPHONE&minPrice=10000&maxPrice=50000&page=0&size=10
```

`PATCH /api/products/{article}/details` меняет название, бренд, цену или доступность.
Пустые поля формы сохраняют прежние значения. Характеристики и камеры не меняются.
`PUT /api/products/{article}` заменяет все поля товара, характеристики и камеры.
Для нескольких групп задних камер используется JSON-запрос.

Примеры JSON находятся в `examples/`, запросы IntelliJ HTTP Client —
в `examples/requests.http`. Артикул для следующих запросов берётся из ответа создания.

### Маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/products/smartphones` | Добавление смартфона через форму |
| POST | `/api/products/tablets` | Добавление планшета через форму |
| POST | `/api/products/laptops` | Добавление ноутбука через форму |
| POST | `/api/products/headphones` | Добавление наушников через форму |
| GET / POST | `/api/products` | Список с фильтрами / создание через JSON |
| GET / PUT / DELETE | `/api/products/{article}` | Чтение / замена / удаление товара |
| PATCH | `/api/products/{article}/details` | Частичное обновление через форму |
| POST | `/api/users/form` | Создание пользователя через форму |
| PUT | `/api/users/{email}/form` | Изменение имени и роли через форму |
| GET / POST | `/api/users` | Список с фильтром по роли / создание через JSON |
| GET / PUT / DELETE | `/api/users/{email}` | Чтение / изменение имени и роли / удаление |
| GET / POST | `/api/brands` | Список / создание бренда |
| GET / PUT / DELETE | `/api/brands/{name}` | Чтение / переименование / удаление бренда |
| GET | `/api/categories` | Список категорий |
| GET / POST | `/api/specifications` | Список / создание характеристики |
| GET / PUT / DELETE | `/api/specifications/{name}` | Чтение / обновление / удаление характеристики |
| GET | `/api/categories/{code}/specifications` | Характеристики категории |
| PUT / DELETE | `/api/categories/{code}/specifications/{name}` | Назначение / удаление связи |
| GET / POST / DELETE | `/api/discount` | Состояние / применение / отмена скидки |

Коды ответов: `201` — создание, `204` — удаление, `400` — неверные данные,
`404` — объект не найден, `409` — конфликт данных или состояния.

Пароли пользователей хешируются BCrypt и не возвращаются в ответах API.
Аутентификация и проверка прав HTTP-клиентов не реализованы.
Таблицы заказов присутствуют в схеме БД, но не обслуживаются API.

## Структура

Пакеты находятся в `com.example.techstore`.

| Пакет | Назначение |
|---|---|
| `model.product` | Товары, значения характеристик, задние камеры |
| `model.catalog` | Бренды, категории, определения характеристик |
| `model.user` | Пользователи и роли |
| `model.discount` | Состояние скидки и исходные цены |
| `repository` | Доступ к данным через Spring Data JPA, фильтрация |
| `service` | Интерфейсы сервисов, проверки данных и расчёт цен |
| `service.impl` | Бизнес-логика и транзакции |
| `controller` | REST-контроллеры |
| `dto` | Данные запросов и ответов |
| `exception` | Исключения и обработка ошибок API |
| `config` | Настройки BCrypt и OpenAPI |

Запрос проходит через контроллер, сервис и репозиторий. Контроллеры зависят
от интерфейсов сервисов. Сущности JPA преобразуются в DTO перед отправкой ответа.

## Тестирование

```sh
make build
```

Тесты используют JUnit, Mockito, `@SpringBootTest` и MockMvc.
Подключение к PostgreSQL отключено тестовым профилем, репозитории заменены моками.
GitHub Actions и GitLab CI настроены на `mvn verify` с Java 17.
