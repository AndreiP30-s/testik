# Короткий разбор перед защитой

## 1. Что делает проект?

Это REST-сервис магазина техники. Через HTTP можно создавать, просматривать,
изменять и удалять товары и пользователей. Данные хранятся в PostgreSQL.
Swagger — готовый интерфейс для отправки этих запросов.

## 2. Как проходит запрос?

Controller принимает запрос и проверяет DTO. Затем вызывает интерфейс сервиса.
Spring подставляет ServiceImpl, где находятся бизнес-правила и транзакция.
Репозиторий Spring Data JPA обращается к PostgreSQL. Ответ преобразуется в DTO и JSON.

## 3. Что означает MVC здесь?

Model — модели и логика предметной области; Controller — HTTP-контроллеры.
Представление результата REST — JSON. Swagger помогает вызывать API и не заменяет
слои приложения.

## 4. Почему один Product, а не отдельные классы смартфонов?

Используется схема EAV из другого предмета. Общие поля находятся в product,
характеристики — в product_specification. Дополнительную характеристику можно
создать как данные. Категории сейчас фиксированы enum и SQL-ограничением.
Цена гибкости — дополнительные проверки значений в ProductRules и CharacteristicValidator.

## 5. Что делает JPA?

@Entity связывает класс с таблицей, @Id обозначает ключ. @ManyToOne — например,
много товаров одного бренда; @OneToMany — характеристики одного товара.
JpaRepository предоставляет стандартные операции, Hibernate выполняет SQL.
Артикул выдаётся последовательностью PostgreSQL через @GeneratedValue.

## 6. Зачем интерфейс сервиса?

Он перечисляет операции. Реализация ServiceImpl содержит их выполнение.
Контроллер зависит от контракта, а не от конкретного класса реализации.
Новый интерфейс не создаёт дополнительную таблицу или HTTP-запрос.

## 7. Как работают фильтры?

ProductFilters создаёт Specification<Product>. Для заполненных параметров
добавляются условия, затем объединяются через AND. Запрос выполняется в БД.
Номер страницы и размер ограничивают выдачу.

## 8. Где наследование пользователей?

User абстрактный, наследники — AdminUser, ManagerUser, CustomerUser.
SINGLE_TABLE означает одну таблицу app_user. Строковый столбец role указывает,
какой подкласс Hibernate должен создать. Полноценной авторизации HTTP-клиента пока нет.
Смена роли меняет тип: репозиторий обновляет role и очищает контекст, чтобы следующий
запрос загрузил правильный подкласс.

## 9. Зачем Persistable?

У пользователя ключ email известен ещё до сохранения. AssignedIdEntity явно
сообщает Spring Data, что новый объект нужно вставить, а не объединить с имеющейся
записью. После загрузки или вставки callback меняет флаг новой записи.
Ограничение PK не позволяет параллельным запросам создать один email дважды.

## 10. Зачем транзакции?

Товар, характеристики и камеры должны сохраняться вместе. При ошибке изменения
откатываются. Во время скидки блокируется строка discount_state; старые цены
сохраняются в discount_backup. Это защищает от повторного применения и позволяет
отменить скидку после перезапуска.

## 11. Где многопоточность?

ParallelPriceService получает коллекцию неизменяемых PriceSnapshot.
ExecutorService рассчитывает цены в потоках price-worker-N, имена выводятся в лог.
JPA-сущности в рабочие потоки не передаются. Сохранение результатов выполняется
в транзакции сервисом.

## 12. Как тесты обходятся без базы?

@SpringBootTest запускает тестовый контекст. @MockitoBean подменяет репозитории.
В тестовом профиле отключены DataSource, Hibernate и создание JPA-репозиториев.
MockMvc отправляет запросы внутри теста. Отдельно проверяется отсутствие
DataSource и EntityManagerFactory. Unit-тесты не проверяют настоящий SQL —
реальное API с PostgreSQL проверялось отдельно.

## 13. Что делает Docker и volume?

Docker запускает только PostgreSQL, Java работает отдельно. SQL выполняется
при первом запуске с пустым volume. Volume сохраняет данные после остановки
и пересоздания контейнера. Порт 5434 на компьютере направлен на 5432 контейнера.

## 14. Что показать на защите?

1. make run; открыть Swagger и показать создание товара через форму.
2. Найти товар, применить фильтры, изменить только цену.
3. Показать соответствующие записи в pgAdmin.
4. Перезапустить приложение и показать, что товар сохранился.
5. Показать многопоточный расчёт скидки и её отмену.
6. Удалить демонстрационный товар.
7. make test при остановленной базе; показать успешные тесты и удалённый CI.

Проговори ответы своими словами и найди каждый упомянутый класс в IDE.
Объяснение именно своего кода полезнее заучивания определений Spring целиком.
