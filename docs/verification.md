# Тестирование

## Запуск

```sh
make test
make build
```

`make test` запускает тесты. `make build` выполняет чистую сборку и Maven verify.
Docker и PostgreSQL для этих команд не нужны.

## Тестовое окружение

В `application-test.properties` отключены DataSource, Hibernate и создание
JPA-репозиториев. Репозитории заменены `@MockitoBean`. REST-запросы выполняются
через MockMvc в контексте `@SpringBootTest`. Отдельный тест проверяет отсутствие
`DataSource` и `EntityManagerFactory`.

Эти тесты проверяют поведение Java-кода и HTTP-контракт. Реальные SQL-запросы
и соответствие JPA-моделей PostgreSQL требуют проверки с запущенной базой.

## Покрытие

- CRUD товаров, пользователей и справочников;
- фильтры и пагинация товаров;
- формы четырёх категорий и частичное обновление товара;
- обязательные характеристики, типы значений, частоты и камеры;
- отклонение null-значений характеристик;
- отрицательная цена, слишком длинное имя и пустой PATCH;
- хеширование паролей и роли пользователей;
- применение и отмена скидки, ограничения изменения каталога;
- параллельный расчёт цен;
- OpenAPI и Swagger UI.

## Результат локальной проверки

17 ноября 2026 года, Java 17: `make build` — 63 теста, без ошибок и пропусков,
`BUILD SUCCESS`.

Запрос через Swagger `POST /api/products` с `"color": null` в характеристиках
вернул `400` и сообщение `specifications[color]: не должно быть пустым`.
